## 다른 환경과 본인 확인

- 커밋 전 코드로 WSL Ubuntu(GCC 15.2, Python 3.14)와 Docker에서 실행해도 판정이 같았다. WSL 빌드 바이너리는 컴파일러가 달라 해시가 `95aed2b0…`로 다르다. 이 실행들은 `code_dirty: true`이므로 공개 증거로 쓰지 않았다.
- 권세현이 2026-11-07 WSL에서 직접 확인한 내용은 [AI 사용 기록](../ai-usage.md)에 남겼다. 평가기 없이 bash `/dev/tcp`로 `HELLO\n`을 보내 받은 `ERR`이 평가기 기록과 같은지, `--target` 모드, 기대값 하나를 바꾸면 그 케이스만 fail이 나는지, 결과 덮어쓰기 거부, 서버 잔류 여부를 확인했다.

## 해석 한계

- 응답의 끝을 "서버가 연결을 닫음"으로 판단한다. 한 연결에서 여러 메시지를 주고받는 본 실험 프로토콜에는 길이/구분자 기준 수신과 세션형 케이스가 필요하다.
- 연습 서버는 한 줄만 읽고 닫기 때문에, 개행 뒤에 바이트를 더 보내는 케이스는 연결 리셋으로 판정이 타이밍에 따라 달라질 수 있어 넣지 않았다.
- 기대값은 공개 README에서 사람이 작성했다. 본 실험에서는 추론 명세에서 기대값을 만들고, 정답 명세와 숨은 평가 입력은 저장소 밖에 둔다.

## 재실행

저장소 루트 PowerShell에서 N05 이미지를 빌드한 뒤 새 결과 경로로 실행한다.

```powershell
New-Item -ItemType Directory -Force runs/n07 | Out-Null
docker compose -f compose.n05.yaml run --rm n05 gcc -O0 -fno-inline -Wall -Wextra -o runs/n07/practice-server practice/n05/ping-server.c
$runTag = Get-Date -Format 'yyyyMMdd-HHmmss'
docker compose -f compose.n05.yaml run --rm n05 python3 -m unittest discover -s scripts -p "test_n07*.py"
docker compose -f compose.n05.yaml run --rm n05 python3 scripts/n07-evaluate.py --cases practice/n07/cases.json --binary runs/n07/practice-server --out "runs/n07/known-$runTag.json"
docker compose -f compose.n05.yaml run --rm n05 python3 scripts/n07-evaluate.py --cases practice/n07/cases-mismatch.json --binary runs/n07/practice-server --out "runs/n07/mismatch-$runTag.json"
```

기대 결과: 모의 테스트 19개 OK. `known`은 `pass 10`과 종료 코드 0. `mismatch`는 `pass 1, fail 4, error 1`과 종료 코드 1. 두 실행 모두 `server_stopped: true`.
